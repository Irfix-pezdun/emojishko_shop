# Магазин эмодзи-паков — Telegram Mini App

Витрина + визитка + сбор заявок для аниматора, делающего кастомные TGS-эмодзи-паки.
Три части: `bot` (aiogram), `backend` (FastAPI), `frontend` (Vite + React).

## Структура

```
/assets/packs/<pack_id>/pack.json   — метаданные пака (необязательно)
/assets/packs/<pack_id>/*.tgs       — сами эмодзи, любые имена
/backend                            — API: каталог, бесплатный эмодзи, заказы
/bot                                — Telegram-бот: /start, админ-команды
/frontend                           — сам мини-апп
.env                                — общие настройки (токен, юзернеймы) — уже заполнен твоими данными
```

Твой пак `pack-001` (100 эмодзи из архива) уже лежит в `/assets/packs/pack-001`.
Отредактируй `assets/packs/pack-001/pack.json`, если хочешь поменять название/теги.

## 1. Установка

Нужны Python 3.11+ и Node 18+.

```bash
# backend
cd backend
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt

# bot (можно тот же venv или отдельный)
cd ../bot
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# frontend
cd ../frontend
npm install
cp .env.example .env   # локально можно оставить как есть
```

## 2. Локальный запуск

Три отдельных терминала:

```bash
# backend (порт 8000)
cd backend && source .venv/bin/activate
uvicorn app.main:app --reload --port 8000

# frontend (порт 5173)
cd frontend
npm run dev

# бот
cd bot && source .venv/bin/activate
python bot.py
```

Открыть мини-апп напрямую в браузере (`http://localhost:5173`) не получится в полном
режиме — Telegram Mini Apps работают только внутри Telegram и требуют HTTPS.
Для локальной проверки UI без Telegram есть флаг `SKIP_INIT_DATA_CHECK=true` в `.env`
(backend примет запросы без проверки подписи) — **только для разработки**, никогда
не включай его в проде.

## 3. Важно про твой токен

Токен бота был прислан в чат с Claude в открытом виде — формально это значит, что он
известен не только тебе. Рекомендую зайти к @BotFather → `/mybots` → выбрать бота →
`API Token` → `Revoke current token`, получить новый и вписать в `.env` вместо старого.
Это займёт 10 секунд и закрывает единственный практический риск в этой истории —
дальше можно спокойно работать с тем, что уже настроено.

## 4. Получить свой Telegram ID (для уведомлений о заявках)

1. Запусти бота (`python bot.py`).
2. Напиши ему `/start`, затем `/myid`.
3. Впиши полученный номер в `.env` как `AUTHOR_TELEGRAM_ID`.
4. Перезапусти бота и backend.

Без этого шага заявки всё равно будут сохраняться в базу — просто не будет личных
уведомлений в Telegram.

## 5. Права бота в канале

Чтобы проверка подписки (`getChatMember`) работала, бот должен быть **администратором**
канала `@IRF_dsgn` (права можно дать минимальные — админство как таковое, без
дополнительных разрешений на посты и т.д.). Добавь бота в администраторы канала
через настройки Telegram.

## 6. Деплой (нужен HTTPS)

Telegram Mini Apps открываются только по HTTPS-адресу. Варианты:

- **Frontend**: любой статический хостинг — Vercel, Netlify, Cloudflare Pages, GitHub
  Pages. Собрать: `npm run build` в `/frontend`, задеплоить содержимое `dist/`.
  Проверь, что `VITE_API_BASE_URL` в проде указывает на адрес backend'а.

  Пошагово под Cloudflare Pages: см. **[DEPLOY_CLOUDFLARE.md](./DEPLOY_CLOUDFLARE.md)**.
- **Backend**: любой сервер с Python — Railway, Render, Fly.io, свой VPS за nginx с
  HTTPS (Let's Encrypt). Не забудь скопировать туда папку `/assets` целиком.
- **Бот**: можно держать на том же сервере, что и backend, процессом polling
  (`python bot.py`) — для такого объёма трафика вебхук не обязателен.

После деплоя:

1. Впиши HTTPS-адрес фронтенда в `.env` как `WEBAPP_URL`.
2. У @BotFather: `/mybots` → выбрать бота → `Bot Settings` → `Menu Button` (или
   `Configure Mini App`) → укажи тот же HTTPS-адрес. Это то, что делает кнопку
   меню/значок мини-аппа рядом с полем ввода в чате с ботом.
3. Перезапусти бота, чтобы кнопка в `/start` тоже вела на прод-адрес.

## 7. Как добавлять/обновлять эмодзи-паки (это отвечает на твой вопрос)

Каталог собирается **автоматически** сканированием `/assets/packs` — вручную большой
manifest.json редактировать не нужно. Два способа добавить эмодзи:

### Способ А — через бота (без доступа к серверу, с телефона)

Эти команды работают только у тебя (по `AUTHOR_TELEGRAM_ID` / `ADMIN_TELEGRAM_IDS`):

- `/packs` — список паков и сколько в каждом эмодзи.
- `/newpack pack-002 Название пака` — создать новый пак.
- `/addemoji pack-002` — войти в режим загрузки, дальше просто шли `.tgs`-файлы
  документами (можно несколько подряд) — они добавятся в пак по порядку.
  Лимит размера одного файла — 500 KB.
- `/done` — выйти из режима загрузки (сразу обновляет кэш каталога на backend).
- `/delemoji pack-002 e003` — удалить конкретный эмодзи; `/delemoji pack-002 last` —
  удалить последний файл в паке.
- `/leads` — последние 10 заявок. Бот ходит в backend по HTTP
  (`API_BASE_URL` + `/api/admin/leads` с Bearer BOT_TOKEN), а не читает SQLite
  напрямую — так бот и API могут жить на разных процессах/машинах.

Это самый удобный вариант для регулярного обновления — не нужен ни компьютер, ни
доступ к серверу, только Telegram.

### Способ B — напрямую файлами

Просто положи `.tgs` файл в `assets/packs/<pack_id>/` (или создай новую папку для
нового пака — сам факт наличия папки с `.tgs`-файлами уже делает её видимым паком).
Изменения подхватятся сами в течение 30 секунд (кэш каталога), либо сразу — если
дёрнуть `POST /api/catalog/refresh` на backend.

Необязательный `pack.json` внутри папки пака задаёт название/теги/обложку:

```json
{
  "id": "pack-002",
  "title": "Мемные реакции",
  "tags": ["мемы", "реакции"],
  "cover": "e001.tgs",
  "order": 2,
  "description": ""
}
```

Если `pack.json` нет — пак всё равно появится в каталоге с именем папки как
заголовком и файлами по алфавиту.

**Удаление эмодзи:** команда `/delemoji <pack_id> <e003|last>` в боте, либо удалить
файл вручную в папке пака. Переименование — пока вручную (файл + при необходимости cover в pack.json).

## 8. Про воронку

- Прямой кнопки "Заказать пак" на главном экране нет — это осознанный выбор из
  брифа: вторичный CTA живёт на экранах "О дизайнере", "Примеры работ" (после
  просмотра пака) и в сценарии "бесплатный эмодзи".
- Мини-апп не принимает оплату — только собирает заявки. Все финансовые детали
  обсуждаются в личной переписке.
- Никакой защиты от "подписался → получил бесплатный эмодзи → отписался" нет —
  это осознанно, как и написано в брифе.

## 9. Известные ограничения / что можно улучшить дальше

- Проверка `getChatMember` требует, чтобы бот был админом канала (см. пункт 5) —
  без этого backend вернёт понятную ошибку вместо молчаливого "не подписан".
- Уведомление автору о новой платной заявке отправляется через Bot API напрямую из
  backend'а (не через процесс бота) — так они не зависят друг от друга.
- SQLite подходит для старта; при желании перейти на Postgres — поменять
  `DATABASE_URL` в `.env`, менять код не нужно (SQLAlchemy).

## 10. Что исправлено относительно первой версии

- `/leads` больше не лезет в БД через `sys.path` — только HTTP admin API.
- Добавлена команда `/delemoji`.
- Лимит размера `.tgs` при загрузке через бота.
- Фон: максимум ~10 одновременных Lottie, остальные — лёгкие CSS-звёзды (меньше лагов на телефонах).
- В `.env`: `API_BASE_URL` (по умолчанию `http://127.0.0.1:8000`).
